# Credit Scoring

Проект посвящён решению прикладной бизнес-задачи — **прогнозированию вероятности дефолта заемщика** (невозврата кредита) на основе исторических данных о клиентах и их финансовом поведении.  
Идея заключается в построении полноценного ML-пайплайна, максимально приближённого к продакшену: от получения и обработки данных до развёртывания API.

- **Бизнес-контекст:** финансовые организации и банки ежедневно принимают тысячи решений о выдаче кредитов. Для снижения рисков важно быстро и надёжно оценивать вероятность дефолта клиента.

- **Цель:** построение и автоматизация MLOps-пайплайна, включающего извлечение и обработку данных, обучение и регистрацию моделей и развёртывание API. Проект демонстрирует навыки end-to-end разработки ML-систем.

## Запуск проекта
### 1. Клонирование репозитория и переход в корневую папку проекта
```bash
git clone https://github.com/talksshowhost/credit_scoring
cd credit_scoring
```
### 2. Создание окружения .env для проекта
Создать файл .env, в котором указано:

   MLFLOW_PG_USER=*Имя пользователя для БД MlFlow*
   
   MLFLOW_PG_PASSWORD=*Пароль для БД MlFlow*
   
   MLFLOW_PG_DATABASE=*Имя БД для MlFlow*

   DATA_PG_USER=*Имя пользователя для БД с обработанными данными*
   
   DATA_PG_PASSWORD=*Пароль для БД с обработанными данными*
   
   DATA_PG_DATABASE=*Имя БД с обработанными данными*

   MLFLOW_BUCKET_NAME=*Название бакета для MlFlow*

   MINIO_ROOT_USER=*Логин для входа в S3/MiniO*
   
   MINIO_ROOT_PASSWORD=*Пароль для входа в S3/MiniO*

   MLFLOW_S3_ENDPOINT_URL=http://localhost:9000
   
   MLFLOW_TRACKING_URL=http://localhost:5000

   AWS_ACCESS_KEY_ID=*KeyID для S3/MiniO*
   
   AWS_SECRET_ACCESS_KEY=*Secret Access Key для S3/MiniO*

   AIRFLOW_UID=50000

### 3. Сборка Docker-образов
```bash
docker-compose build
```
### 4. Запуск всех сервисов
```bash
docker-compose up -d
```
Команда поднимет следующие сервисы:
- Airflow — оркестрация пайплайна (http://localhost:8080)
- MLflow — трекинг экспериментов (http://localhost:5050)
- Application — REST API модели (http://localhost:5555)
- PostgreSQL — хранилище данных
- MinIO — объектное хранилище моделей и данных (http://localhost:9000)
- JupyterLab - Интерактивная среда для анализа данных и экспериментов (http://localhost:8888)

## Стек технологий и библиотек

- **Язык:** Python (основной язык разработки).  
- **Обработка данных:** Pandas, NumPy — очистка, нормализация, создание признаков (feature engineering). SQLAlchemy — работа с SQL-базами.
- **Интерактивная разработка и анализ:** JupyterLab — среда для исследований, прототипирования моделей и визуализации результатов. 
- **Моделирование:**
  - **Традиционные ML:** scikit-learn (Logistic Regression, Random Forest, Gradient Boosting), LightGBM/XGBoost — бустинговые алгоритмы, обеспечивающие высокое качество и интерпретируемость.  
- **Фреймворки MLOps:**  
  - **Airflow** — оркестрация ETL и ML-пайплайна (DAG для регулярных запусков).  
  - **MLflow** — трекинг экспериментов, логирование метрик, регистрация и управление версиями моделей.  
- **Контейнеризация и инфраструктура:**  
  - **Docker + Docker Compose** — развёртывание всех сервисов (API, MLflow, Airflow, БД).  
- **API:**  
  - **FastAPI** — REST-фреймворк для предсказаний модели (вероятность дефолта клиента по его данным).
- **Хранение данных:**  
  - **PostgreSQL** — основная БД для хранения очищенных и агрегированных данных о клиентах.  
  - **MinIO / Amazon S3** — объектное хранилище для «сырых» данных и моделей.  
- **Визуализация:** Matplotlib, Seaborn — построение графиков распределений признаков, важности признаков, матриц корреляции и т.д.

## Этапы реализации проекта

Типовой пайплайн кредитного скоринга включает этапы от сбора данных до мониторинга модели в продакшене.

1. **Сбор и интеграция данных**
   Airflow-DAG ежедневно загружает данные о клиентах, кредитах, платежах и просрочках. Сырые данные сохраняются в S3/MinIO.

2. **Очистка и хранение данных**
   В Airflow организуются задачи предобработки: обработка пропусков, feature engineering. Очищенные данные сохраняются в PostgreSQL.

3. **Разведочный анализ (EDA):**  
   Выполняется в **JupyterLab** — анализ распределений, корреляций и связей между признаками. Визуализация данных и формирование гипотез для feature engineering.

4. **Разработка и обучение модели**
   Создаётся скрипт для обучения моделей (например, LightGBM или Logistic Regression). При каждом запуске логируются параметры и метрики (ROC-AUC, f1-score, Precision, Recall) в MLflow.  
   Airflow-task может запускать переобучение модели при поступлении новых данных.

5. **Оценка модели**  
   Метрики проверяются на кросс-валидации имеющися данных.

6. **Регистрация модели**
   Лучшая версия модели автоматически сохраняется и регистрируется в MLflow Model Registry и в S3 вместе с метаданными.

7. **Развёртывание модели (API)**  
   Модель интегрируется в FastAPI-сервис, принимающий JSON-запрос с параметрами клиента и возвращающий вероятность дефолта.  
   Всё упаковано в Docker-контейнер и собирается через Docker Compose вместе с MLflow, БД и Airflow.

8. **Оркестрация и автоматизация**  
   Airflow управляет всем пайплайном: загрузкой данных, обучением, регистрацией модели и деплоем. Это обеспечивает регулярное обновление и контроль зависимостей между задачами.

## Результаты

Проект демонстрирует полный цикл построения кредитного скоринга — от данных до рабочего API.
